# Size probe: the same test on a library four times the size

This page and the logs beside it were copied from the last rehearsal's repo. Where it says "this repo" or "the sealed runs" it means that rehearsal. Its 18 documents are that rehearsal's, a boat club and a lending library, not this entry's. Its small-library leg is the fresh-clone re-run that `PILOTS.md` also lists.

Run on Sunday 2026-10-11. One pass. Not marked. Not part of any sealed run.

## The question

Every rehearsal used a small library, small enough for a model to search with ease. Does the comparison change when the library is much bigger?

## What we expected

That the folder would do better as the library grew: more to search through without it, and a map that costs little. We wrote that down before running it. It was wrong.

## What was done

- The small library: this repo's 18 documents (31,562 characters).
- The big library: the same 18 plus 34 documents from four earlier practice sets, about unrelated made-up organisations. 52 documents, 123,685 characters.
- The ten questions and their expected answers did not change. All ten are about the original 18 documents.
- The map was regenerated by the same script, so it gained one line per added document. The other three instruction files did not change.
- Three arms, as in `tools/rerun.mjs`: nothing at all, documents only, and the folder loaded first. Ten sessions per arm at each size, on the same day, with the same model and settings as the sealed runs.

## What happened

Means per session.

| | 18 documents | 52 documents |
|---|---|---|
| Documents only: steps | 5.40 | 5.50 |
| Documents only: characters fetched | 7,448 | 9,057 |
| Documents only: tokens in | 21,903 | 22,626 |
| Folder: steps | 2.70 | 2.70 |
| Folder: characters loaded first | 5,148 | 11,685 |
| Folder: characters fetched | 4,707 | 5,001 |
| Folder: characters in all | 9,855 | 16,686 |
| Folder: tokens in | 20,347 | 24,268 |

- Steps did not move in either arm.
- The control read about 1,600 more characters, mostly a longer file listing.
- The folder's loaded text more than doubled, because the map grew from 2,774 to 9,311 characters and is loaded on every question.
- The folder's extra text over the control went from about a third more to about 84% more.
- Tokens in, which favoured the folder at 18 documents, favoured the control at 52.

## What we take from it

- The control does not read the library. It lists the file names, searches for a word and opens two or three files. That costs almost the same at either size.
- A map with a line for every document costs more with every document added, on every question.
- So on this kind of library the folder's case got weaker with size, not stronger.

## What this does not show

- Whether any answer was right. The answers were read by eye and not marked.
- Anything beyond one pass at two sizes.
- What happens where searching is hard: file names that say nothing, questions worded differently from the documents, or very long documents. In this library the file names describe their contents and the questions use the documents' own words.
- Where, if anywhere, the result turns round.

## What is in this folder

- `18-documents/` and `52-documents/`: the raw log of every session, a readable transcript beside each, the questions as sent, and the comparison the re-run tool printed.
- `map-for-52-documents.md`: the map the folder arm loaded at the larger size.
- The 34 added documents are not copied here. They are the `reference/` folders of the earlier practice builds.
